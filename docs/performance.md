# 性能记录

## 已测量

- 一次本地 Markdown 转换记录为 8,907 ms。
- 同一次运行的源文件渲染为 26 页；表格和矩阵的人工视觉复核覆盖跨多页单元格，构成了主要人工等待环节。

这些值是单次运行记录，受硬件、文件复杂度、OCR/渲染工具和审核范围影响；它们不是服务等级或通用速度承诺。

每次新增记录同时写明工具及版本、操作系统或运行环境、文件页数与关键复杂度、是否扫描件、路径/编码条件、各阶段耗时和人工复核范围。缺少这些上下文的数字只保留为本次运行值，不用于跨项目速度比较。

## 已观察到的瓶颈

- 表格合并单元格、跨页课程行和矩阵行/列对齐需要逐页确认。
- 版本差异必须在新候选完成后比较，不能通过跳过复核缩短流程。

## 待验证的速度假设

- 先用 scaffold 记录来源和候选位置，可能减少后续回溯定位时间。
- 将视觉审核按页和唯一决定 ID 组织，可能减少重复审核。
- 复用模板、通用 CLI 和 Schema，可能减少重复搭建与手工改写时间。
- 用 diff 聚焦新增、变化和冲突，可能减少对已确认未变事实的重复审核。

上述假设尚未通过对照测量；不得据此降低验证门槛或承诺耗时。

当新记录与旧性能观察冲突时，先检查工具版本、文件复杂度、缓存、硬件和审核范围。无法解释的差异并列保留为待验证，不用单次更快或更慢结果覆盖历史记录。

若要声称某项复用措施带来提速，记录可比较的前后范围、实际耗时与未改变的审核门槛；没有对照时只记录机制和本次耗时，不给出普遍提速比例。
