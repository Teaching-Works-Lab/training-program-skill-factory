# 复盘：已观察到的结果

以下是一次已完成转换中的观察，不是对其他来源的普遍结论。

- 历史 JSON 与重新核验的候选存在关系差异；因此旧文件只能用于负向比较，不能作为覆盖新版本的输入。
- 课程—指标点的官方单元格与课程—培养目标的追踪结果属于不同证据层。将后者回写为前者会丢失推导路径。
- 自动矩阵提取适合作为候选生成；不明确的符号或端点需要保留为未决，而非最近邻猜测。
- 提取完成不等于核验完成。候选状态在视觉复核之前必须保持 `extracted` 或 `needs_review`。

这些观察支持当前的最小工作流；它们不证明任何培养质量、课程成效或通用提取准确率。

## 经验沉淀门槛

每次踩坑先作为“本次观察”记录，再按证据归类：

| 类型 | 判定 | 沉淀方式 |
| --- | --- | --- |
| 通用 | 机制明确，或在不同来源/运行中重复出现 | 可更新工作流，并说明证据范围。 |
| 条件性 | 只在明确的文件特征、工具版本、路径或平台条件下出现 | 写明触发条件和不适用范围。 |
| 本机特例 | 只与单台机器、安装状态或局部配置相关 | 保留在本次运行记录，不外推。 |
| 待验证 | 单次观察或原因尚未隔离 | 写为假设，不形成固定规则。 |

一次运行至少记录：来源类型与版本、工具及版本、关键运行条件、问题现象、受影响页/字段、实际处理、处理结果、核对证据、阶段耗时和下次预防办法。公开复盘移除私有路径、机构身份和原件哈希。

新经验写入前，先与本文件、`workflow.md`、`pitfalls.md` 和 `performance.md` 比较。出现冲突时保留旧结论和新观察，分别注明证据、适用条件与当前状态；只有证据足以解释差异时，才标明新经验取代或收窄旧经验。
